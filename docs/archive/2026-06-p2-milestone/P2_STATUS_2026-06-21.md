## P2-05 — Execution Edge Cases

**Status:** COMPLETE  
**Verdict:** ACCEPTED  
**Commit:** TBD (2026-06-21)  
**Priority:** P2 blocker — resolved

**Three items required:**

### P2-05-A: Idempotency fail-open on Redis down

**File:** `src/workers/portfolio_scheduler.py` ~line 738  
**Problem:** `_get_fired_signal_ids(session_date, redis_url)` returns `set()` when Redis is unavailable. An empty fired-IDs set means every signal appears "not yet fired" — a duplicate BUY can be submitted on the next cycle if Redis is temporarily down.  
**Required fix:** On Redis connection error, the function should return a sentinel that causes the cycle to abort (fail-safe), not proceed with an empty set (fail-open).

### P2-05-B: Net exposure cap not wired in scheduler

**File:** `src/workers/portfolio_scheduler.py` ~line 450  
**Problem:** `ConstraintEnforcer()` is instantiated without the `net_exposure_cap` keyword argument. The cap enforcement code exists in `ConstraintEnforcer` but is unreachable because the argument is never passed from the scheduler.  
**Required fix:** Pass `net_exposure_cap` from config when instantiating `ConstraintEnforcer` in the portfolio cycle.

### P2-05-C: VolTargeter re-violates cap

**File:** `src/workers/portfolio_scheduler.py` ~line 520 + `src/portfolio/vol_targeting.py`  
**Problem:** `PortfolioVolTargeter` is applied *after* `ConstraintEnforcer.enforce()`. The vol-targeter scales BUY quantities upward to hit the target volatility level, which can push quantities above the cap that the enforcer just set.  
**Required fix:** Either (a) run the VolTargeter before `ConstraintEnforcer`, or (b) re-run `ConstraintEnforcer` after VolTargeter, or (c) apply vol-targeting within the constraint pass.

**What was delivered (2026-06-21):**

- **P2-05-A**: `_get_fired_signal_ids()` now returns `None` on Redis error (fail-closed).
  `_apply_idempotency_filter()` added to exclude S4 BUY orders when skip set is active.
  Caller in `_run_cycle_inner()` sets all S4 symbols in `_idempotency_skip` when `None` received.
- **P2-05-B**: `_load_risk_config()` added; `ConstraintEnforcer` now reads `max_portfolio_exposure`
  and `max_single_asset_pct` from `config/trading.yaml` at each cycle start.
- **P2-05-C**: `PortfolioVolTargeter.scale_orders()` now runs BEFORE `ConstraintEnforcer.enforce()`
  in `orchestrator.py`. Enforcer is the last word — cap cannot be re-violated by vol scaling.
- **P2-05-D** (additional hardening): `_submit_portfolio_orders()` accepts `_on_broker_reject`
  callback; broker rejections are no longer silently dropped.

**Test evidence:**

  `test_idempotency_redis_unreachable_returns_none` (old behavior was the bug being fixed)
